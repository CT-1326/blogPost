# blogPost

## **NestJSベースの高パフォーマンス・イベント駆動型ブログバックエンドAPIサーバー**
> 本プロジェクトは、基本的なCRUDアーキテクチャから出発し、大容量トラフィック環境を想定したデータベースのボトルネック解消およびシステム結合度の緩和のために、RedisキャッシングとRabbitMQ非同期メッセージングを導入したバックエンドアーキテクチャの高度化プロジェクトです。

## 🛠 技術スタック (Tech Stack)
- **Framework & Language:** NestJS, TypeScript
- **Database:** MongoDB, Mongoose (ODM)
- **Caching:** Redis
- **Message Broker:** RabbitMQ
- **Authentication:** JWT (Access Token / Refresh Token)

## ✨ コアアーキテクチャおよび実装スペック (Key Features)
### 1. データレイヤーの最適化および整合性 (MongoDB & Mongoose)
- **インデックスの最適化 (`set index`):** 検索頻度の高いドメインフィールドにインデックスを先制して設定することで、NoSQL環境におけるクエリ実行速度を最適化しました。
- **グローバル論理削除フィルタ (Soft Delete):** `User`, `Post`, `Comment` ドメイン全般にMongooseのpre-middlewareを活用したソフトデリートメカニズムを適用し、データ保存ポリシーを遵守すると同時に、検索時に削除されたデータが自動的にフィルタリングされるよう実装しました。

### 2. 分散キャッシングによる検索パフォーマンスの改善 (Redis)
- **Cache-Asideパターンの導入:** ブログの特性上、読み取り（`Read`）リクエストが書き込み（`Write`）よりも圧倒的に多い検索中心のトラフィックを効率的に処理するため、記事一覧取得APIにRedisキャッシュレイヤーを構築しました。
- **キャッシュ整合性の維持:** 記事の作成（`create`）および修正（`update`）イベントの発生時に、Redis内のキャッシュデータを適切に更新・無効化することで、データの整合性を保証します。

### 3. 非同期イベント駆動型通知システム (RabbitMQ)
- **システムの結合度緩和 (Decoupling):** 記事の作成およびコメント登録時にユーザーへ送信される通知ロジックを、メインAPIスレッドから完全に分離し、非同期イベント駆動型アーキテクチャ（EDA）を検証・実装しました。
- **非同期キュー処理:** 負荷の高い通知送信イベントをRabbitMQにプロデューシングし、バックグラウンドのコンシューマーにメッセージを消費させることで、外部I/Oの遅延がメインのビジネスサーバーの応答性を低下させないよう設計しました。Kafkaに比べ、現在のドメイン規模に適しており、柔軟なルーティングが可能なRabbitMQを採用することで、オーバーエンジニアリングを回避しました。

### 4.実務レベルの認証および権限制御 (RBAC & Security)
- **トークンベースの認証:** JWTベースの`Access Token`および`Refresh Token`スキームを構築し、安全な認証状態の維持とトークン有効期限切れの例外処理を考慮しました。
- **ロールベースのアクセス制御 (RBAC):** JWTペイロード内の`role`値を検証するカスタム`Role Guard`を実装し、管理者（Admin）権限と一般ユーザー権限に応じたAPIエンドポイントへのアクセスを厳格に制御します。

## 📂 디렉토리 구조 (Directory Structure)
```
src/
├── auth/          # JWT認証、Refresh TokenおよびGuardの管理
├── user/          # ユーザードメイン（RBAC含む）
├── post/          # 記事ドメイン（Redisキャッシング連動）
├── comment/       # コメントドメイン
├── notification/  # RabbitMQ Consumerおよび非同期通知処理
└── config/        # 环境変数（env）およびDB接続設定
```
